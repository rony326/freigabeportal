# Freigabeportal 1.2.1

Datum: 2026-11-11 · Tag: `v1.2.1` · Vorgänger: `v1.2.0` (2026-11-11)

Sicherheits-Wartungsversion zu 1.2.0. Ein vollständiger Sicherheitsdurchgang über
das ganze Portal (Anmeldung, Zugriffsrechte, CSRF, XSS/CSP, SQL, Uploads,
Downloads, Maschinenschnittstellen, Backup und die Neuerungen von 1.2.0) hat
**keine kritische und keine hohe Schwachstelle** gefunden. Diese Version schliesst
die kleineren Punkte daraus. Keine Datenbank-Migration, keine neuen
Umgebungsvariablen.

## Wichtig zum Update

**Alle müssen sich einmal neu anmelden.** Das Sitzungs-Cookie hat hinter HTTPS
einen neuen Namen (siehe unten); die alten Sitzungen gelten nicht mehr. Mit der
ChurchTools-Anmeldung dahinter ist das ein stiller Durchlauf ohne Passwort. Am
besten ausserhalb der Hauptzeiten einspielen.

## Geändert

### Sitzung: kürzer und besser geschützt

- Das Sitzungs-Cookie heisst hinter HTTPS **`__Host-portal.sid`**. Der Browser
  akzeptiert ein Cookie mit diesem Präfix nur mit `Secure`, `Path=/` und ohne
  Domain-Angabe: eine andere Subdomain kann es weder setzen noch überschreiben.
  Auf einer lokalen Entwicklungsinstanz über http bleibt der Name `connect.sid`.
- Eine Sitzung gilt **8 statt 24 Stunden**. Wer in ChurchTools aus einer Gruppe
  (Superadmin, Manager, Buchhaltung) entfernt wird, verliert die Rechte damit
  spätestens nach 8 Stunden, auch ohne dass die Person sich abmeldet. Der
  Wechsel der Rechte selbst gilt weiterhin erst nach dem nächsten Personen-Sync
  oder Login.

### Wartungsmodus

- **Warnung bei langer Dauer:** Läuft der Wartungsmodus länger als 4 Stunden,
  weist der Banner (für alle, die weiterarbeiten dürfen) darauf hin, dass im
  Wartungsmodus auch **Sicherheitsalarme zurückgehalten** werden. So bleibt ein
  vergessener Wartungsmodus nicht unbemerkt. Der Beginn wird als
  `wartungsmodus_seit` gespeichert (im Audit-Log wie die anderen Einstellungen).
- **PDF-Downloads (`/downloads/…`):** Wer keine Wartungsrechte hat, bekommt jetzt
  wie die n8n-Routen **503 mit JSON** und `Retry-After: 300` statt der
  HTML-Wartungsseite. Der n8n-Workflow kann so bei einem PDF-Abruf dieselbe
  «später erneut versuchen»-Regel anwenden. Berechtigte sehen die PDF-Vorschau
  weiter.
- Die Pfadprüfungen des Modus sind unabhängig von Gross-/Kleinschreibung. Eine
  abweichende Schreibweise einer Maschinenroute (z. B. `/API/N8N/…`) wird
  ebenfalls gesperrt. Ein Test belegt das.

### Protokoll und interne Aufräumarbeiten

- **Log-Eintrag bei abgelehnten PDFs:** Der Dateiname aus der n8n-Anfrage steht
  im Log jetzt als JSON-Text (höchstens 200 Zeichen). Zeilenumbrüche im
  Dateinamen können keine gefälschten Logzeilen mehr erzeugen.
- **Superadmin-Prüfung an einer Stelle:** Freigabe 2, Spesen-Freigabe 1,
  Ablehnung und die Kontierung prüfen die Superadmin-Gruppe jetzt wie alle
  anderen Stellen über dieselbe Funktion. Das Verhalten ist unverändert; es
  verhindert, dass die Prüfungen künftig auseinanderlaufen. Ein Test schützt
  davor, dass eine handgebaute Prüfung zurückkommt.

## Bewusst nicht geändert

- **Upload vor CSRF-Prüfung:** Bei Formularen mit Datei (Kontierung, Spesen,
  Kreditkarten-Abgleich) wird der Upload vor dem CSRF-Token gelesen, weil das
  Token im selben Formular steckt. Das geht nur mit gültiger Anmeldung, und von
  fremden Seiten wird das Cookie wegen `SameSite=Lax` nicht mitgeschickt.
  Eine Änderung brächte mehr Risiko als Nutzen.

## Hinweise zum Betrieb

- Keine Datenbank-Migration, keine neuen Umgebungsvariablen.
- Reverse-Proxy: Das Portal vertraut dem ersten Proxy davor (`trust proxy = 1`).
  Wer es hinter mehr als einem Proxy betreibt, prüft, dass im Portal die echte
  Client-Adresse ankommt, sonst teilen sich alle Personen dasselbe Rate-Limit.
- n8n: Falls der Workflow PDFs über die signierten Links holt, vor dem nächsten
  Wartungsfenster prüfen, dass er bei 503 erneut versucht.

## Nach dem Update prüfen

1. Anmelden: Der Browser zeigt in den Entwicklerwerkzeugen unter «Cookies» ein
   Cookie `__Host-portal.sid` mit `Secure` und `HttpOnly`.
2. Wartungsmodus kurz einschalten: Eine normale Person sieht die
   Wartungsseite, ein Abruf von `/downloads/…` ohne Anmeldung liefert JSON mit
   503. Wieder ausschalten.
3. Admin → Gruppenrechte und Admin → Personen öffnen: unverändert wie in 1.2.0.

## Tests

2763 automatisierte Tests laufen durch (neu: Sitzungs-Cookie, Wartungsmodus-Dauer,
Downloads im Wartungsmodus, Schreibweise der Pfade, Superadmin-Prüfung).
Browser-Verhaltenstests und die Handy-Layout-Prüfung wurden für diese Version
nicht neu ausgeführt; es hat sich keine Oberfläche ausser dem Wartungs-Banner
geändert.
